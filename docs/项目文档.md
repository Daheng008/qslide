# QSlide 项目文档

> 版本 v1.0.0.3 · 2026-10-18 · 面向开发者

## 1. 项目定位

QSlide 是 **PowerPoint Office.js 加载项**（TaskPane + Ribbon 函数命令），把 QPT（VBA .ppam）验证过的咨询级排版交互基因移植到现代加载项平台：一套代码运行于 macOS / Windows / PowerPoint Web。与 QPT 的本质差异：VBA 走 CommandBars 可复用原生控件；Office.js 不能复用原生 Ribbon 控件，所有能力自研并通过 `PowerPoint.run` 代理对象操作文档。

## 2. 架构与数据流

```
Ribbon 按钮 (manifest ExecuteFunction)
      │ window.qslideXxx()
      ▼
commands/commands.ts ── withEvent 包装（保证 event.completed()）
      │ report(OpResult)
      ▼
localStorage["qslide.notify.v1"] ── storage 事件 + 600ms 轮询兜底
      ▼
taskpane/main.ts 「反馈与提示」区渲染（永不弹窗：成功静默、失败进日志）

核心实现：core/ops.ts（~60 个 op 函数）
  PowerPoint.run(ctx) → getSelectedShapes/Slides → load(items) → 修改 → ctx.sync()
  ⚠ 代理对象跨 run 脱钩：必须在同一 run 内完成 load 与修改（详见 §5 坑 1）

对话框类功能（插入图形/图片）：
  handler ─ displayDialogAsync → src/public/shape-picker.html / picker.html
          ← 页面内 Office.context.ui.messageParent(JSON)
  ⚠ 两个 picker 页面必须自己加载 Office.js（CDN），否则 messageParent 静默失效
```

### 2.1 三层职责

| 层 | 文件 | 职责 |
|---|---|---|
| 清单层 | `manifest.xml` | CustomTab 9 组 50 按钮；资源三节（ShortStrings/LongStrings/Images） |
| 命令层 | `commands.ts` | 62 个 `window.qslideX` handler：调 op → report → completed |
| 操作层 | `ops.ts` | 全部业务逻辑；每个 op 返回 `OpResult{ok, op, detail, api?}` |
| 面板层 | `taskpane/main.ts` + `taskpane.html` | 反馈日志、排版体检报告、取色器/色板、思维模型等面板专属功能 |

### 2.2 Ribbon 分组（v1.0.0.3，对照 QPT 重组为 9 组）

面板（QSlide 面板入口）· 插入（形状画廊/文本框/图片/表格）· 对齐与分布（等间距/居中×3/旋转归零）· 贴合与叠放（贴合↔↕/贴上/下/左/右/置顶/置底/上移/下移一层）· 文本（Action Title/主题标题/脚注/合并文本/删除文本/删空格/字号行距±）· 形状样式（同宽/同高/圆角±/拉直/去轮廓/统一字体/统一色系）· 格式与特效（移除特效/吸取/应用格式/内边距归零/全文档去边距）· 页面（复制所有页/删备注/移除动画/复制幻灯片/灰度优化）· 咨询基因（哈维球½/议程页/价值链）

### 2.3 面板专属功能（不放 Ribbon）

排版体检（扫描本页/全文档 → 报告 → 一键合规）、取色器 + 我的色板、配色方案、频率表、Roadmap 页眉、便签、单位标注、自动换行开关、文本拆形状（Lines2Shapes）、思维模型（2×2 矩阵/金字塔）。

## 3. Manifest 关键约束（Mac PowerPoint 实测）

1. **不支持 `xsi:type="Menu"`（下拉菜单）**——仅 Excel/Word 支持。形状选择用「按钮 + shape-picker.html 画廊」替代。
2. **资源节规则**：`<Description resid>`（Supertip）必须指向 **bt:LongStrings**；Label/Title 用 ShortStrings。Tip 放错节 = 整个加载项被拒。
3. **resid 必须闭环**：控件 `<Icon>` 引用的每个 `Icon.X.16x16` 都要在 `bt:Images` 段有 `<bt:Image id=...>` 定义，且 PNG 文件真实存在于 `src/public/assets/icons/`（vite root:"src" → 静态目录是 `src/public/`）。
4. **重复资源 id**：应避免（实测未触发拒绝但属隐患）。
5. **CustomTab + Label 的结构合法**（官方校验器会误报，忽略）；校验以 `scripts/check_manifest_resources.py` + 真机为准。
6. **函数命令必须调用 `event.completed()`**，否则 Mac 宿主弹「无 UI 外接程序命令」错误框——已由 `withEvent` 包装器统一兜底。

## 4. 开发与发布流程

```bash
npm install
npm run dev                                  # https://localhost:3000（自签证书，root:"src"）
python3 scripts/check_manifest_resources.py  # 改 manifest 后必跑
npx tsc --noEmit                             # 类型检查
npm run build                                # 产出 dist/（正式发布用）
```

**侧载（macOS）**：`bash install-sideload.command` —— 检测并启动 dev server → 拷 manifest 到
`~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/Wef/QSlide.manifest.xml`（自动清理旧文件）→ 信任自签证书。之后 **Cmd+Q 重启 PowerPoint**。

- 只改 JS/HTML：重启 PPT 即可；
- 改 manifest：必须重跑侧载脚本 + 重启 PPT（Office 会**随时清空 Wef 目录**，且把「加载失败」状态缓存在 `OfficeFileCache`——加载项消失时先查 Wef 是否为空、再清缓存：
  `rm -rf ~/Library/Containers/com.microsoft.Powerpoint/Data/Library/Caches/OfficeFileCache{,_15}`）。

**图标**：`scripts/gen_icons.py`（PIL 160 画布绘制 → LANCZOS 缩 80/32/16；透明填充用 `fill=None` 而非 `(0,0,0,0)`）→ `apply_icon_manifest.py` 接线 → 重启 PPT（Office 有图标缓存；图标 URL 404 会静默降级为蓝斜条占位）。

## 5. 实测坑清单（按血泪程度排序）

1. **代理对象跨 run 脱钩**：`getSelectedShapes()` 返回的集合离开 `PowerPoint.run` 即失效，跨 run 修改**静默无效且不报错**。所有读改必须同 run。
2. **加载项整体消失**：§3 的任一清单违规（Menu 控件 / Tip 错节 / resid 悬空）都会让 PowerPoint 拒绝整个 manifest，且 Wef 目录可能被 Office 清空。排查顺序：Wef 内容 → 清缓存 → 资源自检 → 最小 manifest 对照 → 探针二分。
3. **探针二分法**：把可疑组内每个控件拆成独立 manifest（各自新 GUID、Tab 标签 QA/QB/QC/QD）**同时放入 Wef**，重启一次即可按「哪个标签页出现」定位有毒控件（存档见 `临时文件夹/test-manifests/`）。
4. **对话框页面必须自引 Office.js**：`displayDialogAsync` 打开的 picker 页不会自动获得 Office.js，缺了 `messageParent` 就静默无反应。
5. **静默失败三兄弟**：isSetSupported 不达标 / 跨 run 脱钩 / picker 缺 Office.js——表现都是「点了没反应」。面板日志是唯一事实来源。
6. **addImageFromBase64 的 base64 前缀**：不同宿主要求不一，`opInsertImageFromBase64` 已做双格式重试，失败时透传真实错误码。
7. **dev server 是 https**：探活要用 `curl -sk https://localhost:3000/...`，http 探活 000 会误判服务僵死。
